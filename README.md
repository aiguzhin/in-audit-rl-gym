# Fin-Audit RL Gym

Воспроизводимый симулятор для ИИ-аудитора (кейс FinTech №1). Он генерирует вымышленную компанию за один отчётный период, прячет в книгах финансовые ошибки и даёт агенту узкий набор инструментов для расследования. Ответ агента оценивается общим matcher'ом и терминальной наградой.

Это среда для возможного дообучения, а не обученная модель. Веса здесь не обучаются, и об улучшении модели проект не заявляет.

## Запуск одной командой

```bash
# без Docker (Python 3.11, зависимостей нет)
python -m auditenv check

# в контейнере (offline, без GPU)
docker build -t fin-audit-rl .
docker run --rm --network none --cpus 2 --memory 4g fin-audit-rl
```

Команда `check` делает пять шагов и при любой ошибке завершается с ненулевым кодом:

1. Прогоняет 27 тестов среды, сопоставления и награды (`tests/`).
2. Проверяет данные и эталон на 20 эпизодах (5 чистых, 5 с взаимодействующими ошибками, 10 обычных). Для каждого эпизода: бухгалтерские равенства до внесения ошибки, объявленное расхождение после, совпадение эталона с независимой сверкой по открытым записям и достаточность каждого набора доказательств.
3. Запускает четыре базовые политики в изолированном процессе оценщика.
4. Делает 20 парных проверок: повтор seed даёт тот же результат, а смена ID и порядка сохраняет эталон и награду oracle.
5. Строит измеренный разбор сбоев простого алгоритма.

Отчёт пишется в `reports/check_report.json`.

Другие команды:

```bash
python -m auditenv export   # 10 train + 10 dev эпизодов, trajectories/trajectories.jsonl
python -m auditenv demo     # показ эпизода со скриптовой политикой
python -m unittest discover -s tests
```

## Контракт среды

```python
from auditenv.env import AuditEnv
env = AuditEnv(mode="train")             # "eval": награда и диагностика остаются у оценщика
obs, info = env.reset(seed=1001, config={})
obs, reward, terminated, truncated, info = env.step(
    {"name": "list_records", "args": {"table": "ledger", "limit": 50}})
```

| Действие | Что делает |
|---|---|
| `list_records(table, cursor, limit≤50)` | страница из `ledger`, `invoices`, `payments` или `fx`; курсоры стабильны |
| `get_record(table, id)` | одна запись (row_id, invoice_id, payment_id, fx_id; doc_id тоже принимается) |
| `get_document(doc_id)` | документ счёта или платежа |
| `calculator(expression)` | только десятичная арифметика `+ - * / ( )` |
| `submit(findings)` | завершает эпизод (`terminated=true`) |

- Лимит — 100 шагов, отправка тоже считается шагом. Ошибочное действие тратит шаг и возвращает короткую ошибку.
- При исчерпании шагов или 60 секунд эпизод обрывается: `truncated=true`, ответ считается пустым.
- Награда за исследование нулевая. В режиме `train` политика получает терминальную награду. В режиме `eval` политика всегда видит `reward=0` и пустой `info`. Закрытый прогон (`auditenv/server.py`) держит эталон в отдельном процессе и пишет итог в журнал, путь к которому знает только оценщик.

## Данные эпизода

`episodes/<split>/<episode_id>/` содержит `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv` и `policy.json`. Закрытые `truth.json` и `provenance.json` лежат отдельно в `grader_data/` (для открытых train/dev).

Форматы: время — ISO-8601 со смещением, деньги — целые минимальные единицы, курсы — десятичные строки. Отсутствующие ссылки записаны явным `null`.

## Типы ошибок

| Тип | Что меняется в книгах | Сумма |
|---|---|---|
| `duplicate_invoice` | тот же счёт введён и проведён второй раз | итог дубля, валюта счёта |
| `missing_or_partial_allocation` | платёж ссылается на счёт, но в 1200 разнесено меньше, остаток ушёл в 2900 | неразнесённая часть, валюта платежа |
| `fx_conversion_error` | курс чужой даты или опечатка в курсе | разница в базовой валюте |
| `period_cutoff_error` | документ следующего периода проведён в текущем (ловушка: время в UTC выглядит как текущий период) | сумма документа |

Взаимодействующие сценарии:
- `partial_payment_wrong_fx`: частичное разнесение валютного платежа, проведённого по неверному курсу.
- `cutoff_partial_payment_fx`: частичный валютный платёж на границе периода, проведённый рано и разнесённый не полностью.

Правдоподобные корректные отвлекающие случаи: разбитые платежи, частичные оплаты, платёж за несколько счетов, переплата с возвратом, нераспознанные поступления в 2900, еженедельные подписки с одинаковой суммой, документы около полуночи в разных часовых поясах.

## Награда

`clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)`. Сопоставление взаимно однозначное. Вывод считается TP, только если совпадают тип, канонические ID и валюта, сумма укладывается в опубликованный допуск и в доказательствах есть полный допустимый набор. Повтор вывода засчитывается как FP. Неверная структура ответа даёт −1. Код: `auditenv/matcher.py`.

## Базовые политики (20 эпизодов закрытой структуры)

| Политика | P | R | F1 | Возврат | Шаги |
|---|---|---|---|---|---|
| случайный исследователь | 0.00 | 0.00 | 0.20 | −0.61 | 22.9 |
| простой алгоритм сверки | 0.48 | 0.25 | 0.37 | −0.29 | 15.4 |
| «пометить всё» | 0.00 | 0.00 | 0.00 | −1.00 | 2 |
| oracle (только оценщик) | 0.75* | 0.75* | 1.00 | 1.00 | 0 |

\* На чистых эпизодах P и R равны 0 по определению (знаменатель 0), а F1 = 1. Поэтому средние P и R у oracle меньше 1. F1 у случайного исследователя тоже набирается на чистых эпизодах, где он промолчал.

## Честные ограничения

- Модель упрощена: только дебиторская задолженность, один период, книги в базовой валюте. Это не аудиторское заключение.
- Высокая награда не доказывает пригодность для реального аудита.
- Генератор открыт. Поэтому закрытая проверка обязана использовать секретные seed и `secret_salt`, иначе политика может перебрать seed.
- Лимит в 60 секунд измеряется по реальному времени и влияет на результат только в патологических случаях. Остальное воспроизводится побитно.
- Обучение весов не проводилось.

## Сайт

Сайт лежит в `site/`, собирается командой `python site/build.py` и выкладывается на Render как статический сайт (папка `site`).
Страница «Песочница» (`play.html`) запускает пакет `auditenv` прямо в браузере через Pyodide. Копия пакета лежит в `site/py/auditenv/`; после изменения кода обновите её: `cp auditenv/*.py site/py/auditenv/`.
